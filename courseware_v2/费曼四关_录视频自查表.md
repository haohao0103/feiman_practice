# 费曼四关 · 录视频自查表

**用法**：录前过一遍「录前 30 秒」，录中照看「录中实时判断」，录后过一遍「录后 15 分钟」。都要打勾，不能跳。
**依据**：`费曼学习法_录屏评估_第01期.md`（6 分 26 秒那版）＋ `费曼学习法_录屏评估_第02期_20分钟版.md`（20 分 09 秒那版）
**版本**：v3 · 2026-10-24 · 已吸收 20 分钟废片的教训

| 事实 | 数字 |
|---|---|
| 第 1 期计划时长 | 5.4 分钟（讲稿实测 1296 字） |
| 第 1 期实际录成 | **20 分 09 秒** |
| 五步骤被完整讲了几遍 | **3 遍**（00:58 / 05:02 / 08:53） |
| 三种归宿被讲了几遍 | **2 遍**（02:57 / 15:35） |

**关键判断：这不是「讲多了」，是「讲着讲着不确定讲到哪了，两次从头重来」。**

**所以第 0 条检查项是：讲过了就往下走，绝不回头重讲。**

## 录前 30 秒（准备阶段）

| # | 检查项 | 判定 | 勾 |
|---|---|---|---|

| 4 | 本期要用的**每一张图**，最小字号的实际播放端字高 ≥ 14px 吗 | 不达标就重制 | ☐ |

| 6 | 🔴 **编辑器 UI / 系统浮层**会入镜吗 | 上一版录屏出现了编辑器工具栏、macOS 辅助功能浮层、TradingView 工具栏 → **必须关掉** | ☐ |

## 录中实时判断（不是录前，是录的过程中）

**唯一的实时红线：说出「我们可能花时间有点多了」= 该停 = 已经晚了。**

一旦冒出这句话，说明你**正在重讲已经讲过的内容**。处理：

1. **立刻停止重讲**，跳到下一个 `【段 N】` 锚点
2. 在当前段的 `【回炉点】` 记一行：`【回炉点】段 X 讲乱了，重讲了一遍`
3. **不要试图补救** —— 补救就是第 4 遍

**自查动作**：每讲完一段，眼睛扫一下下一个 `【段 N】` 标题还在不在屏幕上方。
看不见锚点 = 已经讲过头了。

## 录后 15 分钟（回炉阶段）

### A. 费曼四关复检（听一遍，不用打分，只回答是/否）

| 关 | 问题 | 勾 |
|---|---|---|
| 关1 · 讲清了吗 | 有没有哪句话，**外行听完还是不懂**？圈出来 | ☐ |
| 关2 · 讲出为什么了吗 | 每个「是什么」后面，**有没有跟上「为什么」**？缺几个就记几个 | ☐ |
| 关3 · 能自我纠错吗 | 录制中有没有当场发现讲不通的地方？**记下来了吗** | ☐ |
| 关4 · 能落到例子了吗 | 观众看完**能不能自己用**？有没有至少一个具体形态 | ☐ |

### B. 回炉（这一步不能省）

| # | 动作 | 勾 |
|---|---|---|
| 1 | 把录制中的**卡壳点 + 现场疑点 + 说错的表述**列成清单 | ☐ |
| 2 | **改回源文件**（讲义 / 课件 md / 图），不是改记忆、不是"下次再说" | ☐ |
| 3 | 改完后**重读一遍**改过的段落，确认新说法自己也讲得顺 | ☐ |
| 4 | 数字类表述**补上出处与条件前缀** | ☐ |
| 5 | 🔴 **复跑预算校验并同步头部**：`python3 scripts_pa/verify_script_budget.py --sync` | ☐ |
| 6 | 🔴 核对实际时长 vs 声明时长，偏差 >20% 记一条（说明又即兴了） | ☐ |

### C. 第 5 步 · 60 秒外行版复测

| # | 动作 | 勾 |
|---|---|---|
| 1 | 抽本期**一个核心概念**，不用术语、不看稿，讲 60 秒并录下来 | ☐ |
| 2 | 回听一遍：有没有出现「只有内行才懂的词」 | ☐ |
| 3 | 有 → 把该术语换成大白话，**改回源文件** | ☐ |

## 三个硬指标（每期看这三个数就够了）

| 指标 | 目标 | 为什么 |
|---|---|---|
| **盲讲卡壳点数量** | ≥ 2 个/期 | 0 个 = 你在念稿，不在学。卡壳点就是你的理解缺口清单 |
| **回炉改回源文件的条目数** | ≥ 1 条/期 | 0 条 = 这一期白录了，同样的坑下一期还在 |
| **60 秒外行版复测通过** | 每期都做 | 这是费曼第一关唯一能客观验证的方式 |

## 新增两个量化指标（针对 20 分钟废片）

| 指标 | 目标 | 怎么测 | 为什么 |
|---|---|---|---|
| **重复内容占比** | < 10% | 评估流水线 `volume_check.json` → `重复体量.占总讲述比例` | 上一版 26.2%，是超时的直接原因 |
| **实际 vs 声明时长偏差** | < 20% | `probe_meta.json` 时长 ÷ 讲稿头部声明时长 | 上一版 +273%，说明即兴失控 |

## 常见坑（我见过的）

| 坑 | 后果 | 对策 |
|---|---|---|
| 🔴 **讲着讲着不确定讲到哪，从头重讲** | 20 分钟里 5 步骤讲了 3 遍，超时 3.7 倍 | `【段 N】` 锚点 + 铁律 1 + 录中实时判断 |
| 🔴 **讲稿头部时长是虚高的** | 照着虚高 73% 的目标录，必然超时 | `verify_script_budget.py --sync` 自动同步，偏差 >10% 即 FAIL |
| 照稿录，不盲讲 | 零理解缺口暴露，永远不知道自己不懂什么 | 先盲讲 3 分钟 |
| 现场发现错误，嘴上改完就过 | 同一个坑每一期重新发现一次 | **改回源文件**（本表 B-2） |
| 即兴加没验证的强表述 | "充分必要""必然"这类词一旦出口就是硬伤 | 录前第 8 项 |
| 图上小字在手机上糊 | 观众在手机上刷到就划走 | 最小字号 ≥ 20pt + 满屏显示 |
| 编辑器 UI / 系统浮层入镜 | 观感立刻掉档次 | 录前第 6 项 + 录后 B-6 查时长 |
| 只讲"是什么" | 观众记住了结论但不会用 | 关2：每个"是什么"后面追一个"为什么" |
| 术语堆砌 | 外行听不懂就划走 | 关1：圈出所有没解释的词 |
| 结尾没有动作 | 观众听懂了，但不知道该干什么 | 每期结尾必须留一段「交给观众一个动作」 |
